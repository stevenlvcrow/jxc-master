# 出入库、采购链路、档案主数据与盘点准备测试执行方案

## 目标

本方案用于验证采购前置链路、库存出入库、自动出库、调拨、报表事实追踪、工作流执行和数据权限控制。测试数据必须保留为后续盘点业务基线，不允许测试后随意清理。

统一测试标记：

- 数据备注：`QA_INV_E2E`
- 集团编码：`QA-GRP-A`、`QA-GRP-B`
- 门店编码：`QA-A1`、`QA-A2`、`QA-B1`
- 物品编码前缀：`QA-`
- 单据备注：必须包含 `QA_INV_E2E`

## 测试资产

- 主数据和库存基线脚本：`jxc/scripts/qa-inventory-e2e-seed.sql`
- 事实流水、报表和权限核验脚本：`jxc/scripts/qa-inventory-e2e-assertions.sql`

执行顺序：

1. 启动后端并确认 `schema.sql`、`seed-core.sql` 已完成初始化。
2. 使用 `psql` 在目标库执行 `qa-inventory-e2e-seed.sql`。
3. 登录 QA 账号执行采购、库存、调拨和盘点前置业务。
4. 每完成一批单据审批后执行 `qa-inventory-e2e-assertions.sql`。
5. 保存核验结果作为后续盘点基线。

## 档案主数据准备

脚本必须准备以下数据，缺失即测试准备失败：

- 单位：至少覆盖 `斤/公斤/克/个/箱/袋/瓶/包/份`。
- 物品类别：至少 12 类，覆盖蔬菜、肉类、水产、调料、面点、预制菜、酒水、一次性用品、前厅类、日用百货、半成品、成品。
- 供应商：至少 8 个启用供应商，覆盖集团/门店来源、有/无供货关系、供应商管理库存、不同税率。
- 仓库：每个 QA 门店至少 4 个仓库，覆盖普通仓库、出品及生产部门、行政部门、退货/调拨场景仓。
- 物品：每个 QA 门店至少 40 个启用物品，集团维度至少 20 个共用物品。
- 用户：平台、集团、门店、业务员、审核员、跨门店、跨集团账号均可登录，初始密码 `123654`。

物品组合要求：

- 基础物品：单单位物品，用于采购、普通入库/出库、盘点无差异。
- 多单位物品：箱/袋/斤/克等换算，用于采购单位、库存单位、盘点单位一致性。
- 批次物品：启用批次管理和保质期，用于批次追踪、采购入库、销售出库、客户退货、盘点批次差异。
- 生产/菜品消耗物品：原料、半成品、成品，用于生产入库和菜品消耗出库。
- 特殊控制物品：默认不盘点、禁用、无供应商、无库存、低库存、库存不足。

## 采购到入库链路

必须按以下链路执行，禁止跳过前置单据直接造采购入库：

1. 采购单申请 `PURCHASE_APPLICATION`
2. 采购订单 `PURCHASE_ORDER`
3. 采购收货单 `PURCHASE_RECEIPT`
4. 采购入库 `PURCHASE_INBOUND`

每个环节必须校验：

- 创建人只能提交，不能审批。
- 审核员能在审批提醒看到待审记录，点击单号可进入详情。
- 非当前节点角色不能审批，直接调用接口也必须失败。
- 审批通过后待审提醒移除，已审核记录可查。
- 下游单据必须保留来源单号，采购入库能反查采购收货单、采购订单、采购申请。
- 只有采购入库审批通过后才允许写库存余额和库存流水。

## 库存业务覆盖

| 分组 | 业务 | 编码/入口 | 关键验收 |
| --- | --- | --- | --- |
| 入库 | 移库入库 | `STOCK_TRANSFER_INBOUND` | 审批后入库仓增加，流水为正数 |
| 入库 | 生产入库 | `PRODUCTION_INBOUND` | 审批后生产仓或普通仓增加 |
| 入库 | 其他入库 | `OTHER_INBOUND` | 不同入库原因进入其他出入库汇总 |
| 入库 | 采购入库 | `PURCHASE_INBOUND` | 能回溯采购申请到入库完整链路 |
| 入库 | 客户退货入库 | `CUSTOMER_RETURN_INBOUND` | 客户和退货原因进入明细报表 |
| 出库 | 菜品消耗出库 | `DISH_CONSUMPTION_OUTBOUND` | 自动出库分组入口，专用报表一致 |
| 出库 | 自动出库 | 自动出库分组 | 自动生成数据不得绕过库存事实流水 |
| 出库 | 客户销售出库 | `CUSTOMER_SALES_OUTBOUND` | 审批后扣减库存，客户可追踪 |
| 出库 | 报损出库 | `DAMAGE_OUTBOUND` | 报损原因、数量、库存扣减一致 |
| 出库 | 其他出库 | `OTHER_OUTBOUND` | 不同原因进入其他出入库汇总 |
| 出库 | 移库出库 | `STOCK_TRANSFER` / `STOCK_TRANSFER_OUTBOUND` | 出库仓扣减，与移库入库闭环 |
| 出库 | 采购退货出库 | `PURCHASE_RETURN_OUTBOUND` | 采购退货审批后扣减库存 |
| 调拨/领料 | 部门领料 | `DEPARTMENT_PICKING` | 部门、仓库、物料维度可查 |
| 调拨/领料 | 三方调拨单 | 订单侧入口 | 源单生成或关联库存单据后可追踪 |
| 调拨/领料 | 调拨分组 | `/inventory/transfer-groups` | 配置影响可选调拨范围，不直接产生流水 |
| 调拨/领料 | 部门调拨 | `DEPARTMENT_TRANSFER` | 调出/调入逻辑按系统规则校验 |
| 调拨/领料 | 店间调拨 | `STORE_TRANSFER` | 调出和调入门店权限隔离 |

## 事实流水与报表核验

每张库存单据按状态分三类核验：

- 草稿、已提交、驳回：不得影响 `inventory_balance`，不得产生 `inventory_transaction`，不得出现在出入库报表。
- 已审核：必须产生 `inventory_transaction`，库存余额和流水 `after_qty` 一致。
- 反审核或取消审核：必须按当前业务规则生成反向事实或禁止操作，不能只改状态不改库存。

已审核单据必须至少核验这些字段：

- `biz_type`
- `biz_id`
- `biz_line_id`
- `warehouse_name`
- `item_code`
- `quantity_delta`
- `before_qty`
- `after_qty`
- `operator_id`
- `created_at`

报表入口：

- 出入库明细：`/api/inventory/inout-detail/report`
- 库存出入库汇总：`/api/inventory/inventory-inout-summary/report`
- 库存收发汇总：`/api/inventory/stock-inout-summary/report`
- 其他出入库汇总：`/api/inventory/other-inout-summary/report`
- 组织间调拨明细：`/api/inventory/inter-org-transfer-detail/report`
- 组织间调拨汇总：`/api/inventory/inter-org-transfer-summary/report`
- 菜品消耗出库报表：`/api/inventory/dish-consumption-outbound/report`
- 批次追踪：`/api/inventory/item-batch-trace/report`

## 数据权限反越权

必须使用 QA 账号分别验证：

- `SELF`：只能看本人创建数据，不能看同门店其他人创建的数据。
- `STORE`：只能看本门店数据，不能看同集团其他门店。
- `GROUP`：只能看本集团和下属门店，不能看其他集团。
- `PLATFORM`：可看全部 QA 数据。
- 直接拼接其他组织 `orgId`、其他单据 ID、报表参数、导出接口都不得越权。

前端隐藏按钮不算通过，必须同步验证接口拒绝或返回空结果。

## 盘点基线

采购入库形成主库存基线，出库、退货、调拨用于制造流转和差异。盘点前必须导出并保存：

- 集团
- 门店
- 仓库
- 物品编码
- 物品名称
- 批次或批次标记
- 单位
- 账面数量
- 账面单价
- 来源单据链
- 最后一条 `inventory_transaction.id`

后续盘点测试至少覆盖：

- 全仓盘点无差异
- 指定物品盘盈
- 指定物品盘亏
- 多人盘点生成
- 默认不盘点物品排除
- 批次物品追踪

## 缺陷判定

- 档案数据不足导致业务无法执行，判定测试准备失败。
- 已审核库存单据缺少事实流水或报表数据，判定失败。
- 未审核、待审、驳回单据影响库存或报表，判定失败。
- 越权用户能查看、审批、导出或通过接口读取非授权数据，判定失败。
- 工作流节点、提醒、菜单、按钮和接口权限不一致，判定失败。
- 不做兼容兜底；发现主数据缺口、流程缺口、事实流水缺口、报表缺口或权限缺口，直接记录缺陷。
